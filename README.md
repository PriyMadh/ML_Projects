# ML_Projects
This README file will explain each of these projects found in this repository, EXCEPT the migraine and music ones, because those are also found in separate repositories as part of a larger overall project.

1. cardio_vascular_disease_risk.py:
   I made this project after learning about the basics of logistic regression from Andrew Ng's Machine Learning Specialization on Coursera. Here, I implemented logistic regression and L2 regularization (stopping the weights from getting too high and overfitting) (regularization was also done so I would understand how to do it in the future, not specifically because this model was prone to overfitting) from scratch using basic Python and NumPy. The dataset was from Kaggle, as it seemed like a fun project to do: to predict whether someone would have cardiovascular issues or not--and it fit in well with learning logistic regression. This code is partially vectorized in that it goes training example by training example, but does not go training example 1, feature by feature, training example 2, and so on. I think the main issue here was that many of the features were unscaled and continuous, and some of them were much higher than others with much larger ranges, so small changes in different weights would give greater importance to certain features. What helped was scaling all the features down by a factor of 100 so that they were closer to 0-1, and also so that my learning rate wouldn't have to be too small (if I didn't scale, then it may have kept bouncing around the cost function if the slopes were too high and it kept overshooting. I think maybe, looking back, mean normalization would've been better here because then some features that were already like maybe between 0 and 5 wouldn't have to have been scaled down as much as features that were going up to like 200.

2. house_prediction_model.py:
   This was the first machine learning project I ever made, and I made it right after learning about linear regression and gradient descent for the first time. This is also built from scratch using the mean squared error cost function and running gradient descent as the optimization algorithm. This is completely built off of for loops and embedded for loops (not vectorized), mainly because I have never really taken any linear algebra class, and all of what I know is self-taught, so I wanted to understand how the math works under the hood by writing it out and visualizing it. There are only 5 training examples, and they were entered manually by me after I found some houses on Zillow. I figured a house price prediction model is a good way to start learning linear regression, so that's what made me choose this for my project. Otherwise, it's pretty straightforward, and if I had to say the biggest challenge about making this, it would just be wrapping my head around the math.

3. number_recognizer.py:
   This was my first foray into Neural Networks (I used TensorFlow, though I understand some of the basics of backpropagation--I just have to completely wrap my head around it--and will be looking to make a neural network from scratch in the future, just for fun), and it's pretty much a cliché project that I actually picked up from Andrew Ng's course. It's a digit recognizer where the digits are in black and white, so I could basically treat every image as a matrix of numbers (0 or 1 (i scaled down by 255) depending on whether the pixel had a color or not, and then unroll the matrix into a vector (say, a 20x20 image into a 400-element vector) and use each vector (thereby each image) as a training example. The dataset came from Kaggle, and it also had a test dataset along with it, and the algorithm actually performed really well on the test data, so that was really exciting. Anyway, the hidden layers are both ReLU activation layers, and then the output layer is actually linear, not softmax, because there are some rounding errors when using softmax layers, so using a linear layer, then taking the logits from that layer and comparing them to each other is the best way to determine which digit was most likely passed through the model for inference. Then I used the test data to test the predictions by first rolling out the pixel matrix into a vector, sending it into the model, and then reshaping it back into the matrix and plotting it, and displaying the prediction along with it.

4. warehouse_optimizer_k-means.py:
  This was my first unsupervised learning project and basically I got the idea from my track/biking coach who used to be a UPS delivery man, and he would talk about how some houses were super far from the warehouse, so when I was learning about k-means, I just throught it would be cool to treat each point as a two-dimensional vector (x and y coordinates) and use k-means algorithm to find optimal points for the warehouses (the centroids), and it worked out pretty well I think. Obviously, though, it isn't perfect, as many other factors should be taken into consideration, such as routes, speed limits, z-position, and traffic at certain times of day when goods need to be exported, along with proximity to places where they get the goods in the first place, but I thought it was a cool experiment to start with. Basically, k-means works by randomly selecting certain positions for the centroids, calculating the distance of each point to a centroid, assigning the points closest to a centroid to that centroid, then moving the centroid to the mean of the collective points closest to it, and running the same process over and over until the centroids converge.
